01 / Design Intent

六个目标，决定了整个仓库的形状

01 / Unified Runtime

交互式与自动化共用执行核心

TTY、JSON、NDJSON 和 Node Host 共享 SessionRuntime，不各自复制 Agent 逻辑。

02 / Hard Boundaries

Agent 定义、执行编排与展示拆分

Agent 包只定义能力；只有 Orchestrator 构建并运行完整 Session。

03 / Workspace Safety

工具始终在受控文件系统边界内

Real Path、符号链接复检、Shell Sandbox、Permission Profile 共同收敛权限。

04 / Long Horizon

Session、Checkpoint、Task、Memory

长任务可分 Stage 运行、压缩上下文、跨进程恢复，并保留稳定状态边界。

05 / Observable by Default

每一步都进入 Run 级事件协议

模型、工具、Handoff、Skill、Memory、Hook、Eval 都映射成 Atomic Atom。

06 / Quality Gate

“模型说完成”不等于真正完成

领域 Validator + Eval DAG + Completion Policy 决定接受、重试或拒绝。

关键不变量：Hook 的 allow 不能覆盖 Runtime 的 deny；Studio 永远拿不到 Runtime 权限。

四层结构：宿主、执行、策略、协议

依赖只能向下。基础包不认识 CLI，也不认识某一种具体 Agent。

04 / Host Model

同一个核心，四种接入深度

入口不是同义封装。越靠近底层，宿主承担的资源、策略和持久化责任越多。

Persistent Host

SessionRuntime

Stage、预算、持久状态、Checkpoint、Task、消息、压缩与恢复。

Multi-turn Host

AgentSession

多次 submit()，负责 Hook、Memory、Prompt Expansion、History 和 Eval。

Single-turn Host

runAgentSession()

兼容入口；自动创建并关闭 AgentSession，适合短生命周期 Node Host。

Runner Adapter

执行已构建的 Agent；不解析项目配置，也不拥有持久 Session。

05 / Runtime Anatomy

一次 Prompt，不只是一轮模型调用

顶层 Prompt 对应一个 Atomic Run；一个 Session 可以跨多个 Stage。恢复只发生在已持久化的稳定 Stage 边界，不序列化 SDK 内部 RunState。

06 / Request Lifecycle

从 submit 到 accepted，共 12 个关键边界

  1. Host 提交 Prompt，Runtime 打开或恢复 Session Lease。
  2. Config 合并用户/项目配置并校验所有引用与预算。
  3. Hooks 运行 SessionStart、UserPromptSubmit 与 Expansion。
  4. Memory 在 Agent 构建前召回并注入有界上下文。
  5. CapabilityScope 计算 Agent、Skill、MCP、Workspace、Policy 的交集。
  6. AgentFactory 按节点 type 构建 Code、Research 或自定义 Agent。
  1. Runner 调用模型，统一处理 Tool、Handoff、Usage 和取消。
  2. Tool Middleware 校验 Effect、Permission、Hook，再执行并规范化结果。
  3. Validator 在模型输出后执行领域确定性验证。
  4. Evals 执行 DAG Check、Scorecard 与一次可控修复。
  5. Completion Policy 输出 accepted / degraded / retry / review / rejected。
  6. Memory Promotion 只有 accepted 输出自动提取并晋升长期记忆。
submitrunId 创建，Stage 计时开始
prepareHook + Memory + Scope + Graph
executeModel ⇄ Tool 循环
verifyValidator + Eval + Repair
persistHistory + Task + Checkpoint + Flow

Stage 停止原因：完成 / Turn、Tool、时长、无进展预算 / 用户交互 / 取消 / Provider、Tool、Hook、Validator、Eval 失败

核心逻辑不是在模块间传递一份可变大对象，而是：命令驱动 Stage，最小能力约束副作用， Envelope 与 Atomic Event 记录事实，Artifact/Receipt/Scorecard 提供完成证据，投影层只读重建界面。

安全风险如何处理

Prompt / Memory Injection

Memory 以“不可信数据”边界注入；Prompt、Tool 输出和 Atomic Payload 都做长度限制。项目内容不能提升权限，异常输入进入 Validator/Eval。

Path / Symlink Escape

路径从 Workspace Root 解析，读写前后复检 Real Path；拒绝 ..、符号链接逃逸和命令内 cd 越界，违规直接 hard deny。

Shell / Network Side Effect

Tool 先按 Effect 分类，再合并 Permission Profile 与 Hook 决策；Shell 优先进入平台 Sandbox，显式 Host Policy 降级必须记录边界变化，远程脚本直管道仍为硬拒绝。

MCP / Hook / Secret

MCP Target 取多层 allowlist 交集；Hook 校验来源 Hash、HTTPS 和公网地址。Header 环境变量显式允许，日志与事件只保存脱敏摘要。

06C / Runtime Sequence

一次 CLI Submit 的真实时序

时序重点：Memory Recall 在 Agent 上下文构建前；Tool Hook 包围副作用；Memory Extraction 和 Evals 都在最终输出之后；Context Compact 由预算判断或 /compact 触发。

Graph 决定“是谁”，Scope 决定“能做什么”

Agent Graph Node

09 / Research Agent

搜索结果不是证据，URL 也不是论证

Research Agent 把检索、Evidence、Claim、反证、Citation 与 Eval 建成一条可验证链。 每个 Run 使用独立 Ledger，避免并发研究互相污染。

SearchProvider Web Search
Evidence规范 URL、来源、时效、摘要
Claim支持、反驳、冲突、重要性
ReportCitation Validator + Evals

Evidence Ledger

默认最多 50 个规范 URL；保存来源类型、访问时间、支持/反驳关系与验证状态。

Claim Ledger

默认最多 200 个结构化论断；关键事实先进入 Manifest，再检查 Citation 完整性。

10 / Multi-agent

Handoff、Delegate、Subagent 不是三个名字

Current SDK Run

Handoff

控制权转移给目标 Agent。

适合专业路由；父 Agent 不等待一个“工具结果”后继续。

Bounded Tool Call

Delegate

父 Agent 等待结果并继续。

适合并行分析、审查与研究；目标必须在 delegates allowlist 中。

Persistent Session Profile

Session Subagent

可复用专家角色与运行实例分离。

通过 /agent-new、/agents、/agent:<name> 创建和运行。

Main Agent 何时 Spawn Subagent

Runtime 不根据“任务看起来很复杂”静默创建子 Agent。只有协作能力已经进入当前 Capability Scope，且 Main Agent 或用户触发了明确入口时才会 Spawn。

10B / A2A Security Boundary

Envelope 负责关联，Runtime 负责授权与隔离

当前 A2A 是 Yiku 进程内消息协议，不是开放网络协议。消息携带稳定身份和因果键， 但接收消息不会授予任何 Tool、Workspace、Skill 或 MCP 能力。

AgentMessageEnvelope PROCESS INTERNAL
Identity eventId · sessionId · agentId · agentSessionId · occurredAt
Causality parentAgentId · parentToolCallId · taskId · toolCallId
Payload Union agent_spawned · agent_output · agent_finished · tool_called · tool_output · usage · hook_decision
Delegate Request agent_key · prompt · access_mode · isolation · task_id
Bounded Result output · changedFiles · patch · verification · worktreeId
01 · 目标与输入先校验 Delegate 目标必须进入父 Agent 的 allowlist；Strict Schema 拒绝未知字段、空任务和非法访问模式。
02 · 能力只能缩小 父范围 ∩ Agent Type ∩ Skill Snapshot ∩ MCP Allowlist ∩ Workspace Scope；子 Agent 不能继承未声明能力。
03 · 文件数据默认只读 Reader 受并发预算限制；只读任务若报告 changedFiles 立即失败，不把结果伪装成成功。
04 · 写入按隔离级别执行 Shared Writer 进入单写锁；Worktree Writer 使用独立目录并只返回 Patch。显式要求 Worktree 时创建失败直接终止。
05 · 副作用和结果双重治理 Tool Middleware、Permission、Hooks、Sandbox 约束执行；Validator 始终生效，工业 Eval 由具体调用路径配置。
NETWORK BOUNDARY 若未来暴露为 HTTP A2A，还必须增加双向身份认证、租户绑定令牌、消息签名与重放保护、 每租户 Store/Rate Limit。当前进程内 Envelope 不能直接当作不可信网络协议使用。
11 / Atomic Flow

把“Agent 在做什么”变成确定性事件协议

AtomicDefinition { key: string kind: AtomicKind label: string level: "deep" | "runtime" } AtomicInstance { id: string iteration?: number parentId?: string }
AtomicFlowEvent { eventId: string runId: string sequence: number atom: AtomicDefinition instance: AtomicInstance phase: AtomicPhase edge?: AtomicEdge payload?: BoundedSummary }
scheduled可选：进入调度队列
start同一 Instance 开始
delta × N有界增量，不创建新实例
end / error终态必须复用 Instance ID
fold按 sequence 重建状态

Sequence

单 Run 严格递增；Fold 拒绝倒退与混合 Run。

Parent

表达层级，不替代流程因果。

Edge

execution / data / feedback / persistence。

Payload

只允许有界摘要；禁止密钥、完整 Prompt、无限 Tool 输出。

13 / Observability

观测失败可以降级，但不能拖垮执行

Sink 隔离

每个 Sink 保序队列独立推进；失败记录降级码，其他 Sink 继续。

确定性投影

相同事件前缀得到相同 Fold State 与 Trajectory；支持 throughSequence。

只读 UI

Observatory 不创建、取消或修改 Agent Session；状态不反向控制 Runtime。

Explainable Recall

Working Memory

14B / Memory Taxonomy

先定义语义，再决定是否值得长期保存

Store 持久化五种 MemoryKind，运行时再投影为三类长期记忆； working 是当前 Session 的短期层，不会自动晋升。

scenario 具体场景中的选择与经历：decision + episode
procedure 可重复执行的方法：procedure
semantic 可复用知识与稳定偏好：fact + preference
scenario / decision

Decision

记录已做出的选择、适用上下文和关键理由；不是脱离场景的永久规则。

例：本仓库采用 tsc -b，因为各包使用 Project References。
scenario / episode

Episode

记录一次发生过的事件、过程与结果，用于相似场景复盘，而非抽象步骤。

例：上次构建因 Node 版本过低失败，升级到 22.13+ 后恢复。
procedure / procedure

Procedure

记录可重复执行的步骤、顺序与完成条件，适合直接指导后续操作。

例：先跑受影响包测试，再执行 pnpm lint 与 pnpm build。
semantic / fact

Fact

记录可验证、相对稳定的项目或领域事实；事实变化时应更新 Revision。

例：Yiku 要求 Node.js ≥ 22.13.0，包入口使用 ESM。
semantic / preference

Preference

记录用户或团队持续有效的表达、工具或工作方式偏好，不保存一次性要求。

例：工程说明保持简洁；代码检查只使用 Biome。
working / session only 当前任务目标、中间结论、待确认项和工具观察；跟随 Session State， 只有通过 Extraction + Policy + Consolidation 才可能转成上述长期 Kind。

Decision Policy

冲突显式化

显式 Trust

17 / Evaluation

完成不是布尔值，而是一条决策链

ProfileCheck、依赖、权重、阈值、预算
Plan校验重复、缺失、依赖环、Digest
SchedulerDAG 并发、Abort、超时

Policy完成决策 + 有界修复
accepted / degraded

可以交付

达到质量与硬门禁；可选基础设施降级时保留明确标识。

retry / needs-review

修复或人工判断

修复保持同一 Task、创建新 Attempt；未知副作用和证据不足进入复核。

rejected

硬门禁失败

Blocker、Secret、Boundary Violation、Artifact Drift 不能被平均高分抵消。

Code Evals

Artifact Integrity、Change Scope、Verification Command；isolated 命令默认禁网。

Research Evals

Claim/Citation、冲突、独立域多样性、时效、权威性与报告结构；默认质量阈值 0.8。

默认调度上限：4 checks / run · 8 concurrent runs · 32 checks / run · maxRepairAttempts = 1

Implementation path 
const plan = planner.createPlan({
  profile, runId, taskId
});
await store.writePlan(plan);

for (;;) {
  const context = createContext(output, evidence);
  const scorecard =
    await scheduler.run(plan, context);
  await store.writeAttempt({
    attempt, evidenceIndex, scorecard
  });

  const decision = policy.decide({
    scorecard, operationReceipts,
    canRepair, repairAttemptsUsed
  });
  await store.writeDecision(decision);

  if (decision.action !== "retry") return decision;
  output = await repair(decision.repairInstruction);
}

Component Architecture / Flow

Atomic Flow 是运行事实总线，不是 UI 状态容器

Flow 的核心职责是把一次 Run 内的所有事实稳定排序、分发和持久化。它不执行 Agent， 不解释业务结果，也不要求每个投影都在线。

Producer Contract Runtime、Agent Observer、Memory、Hook、Eval、Research Tracker 都只发有界事件摘要。
AtomicFlowRun 分配 Run 内递增 sequence，维护 buffer、subscriber 和 sink 队列。
Sink Isolation JSONL、Studio、Trace Receipt 各自保序；某个 Sink 失败只标记 degraded。
Fold / Replay 按 sequence 重建实例状态、边、终态和降级信息；混合 Run 或倒序直接失败。

Component Architecture / CLI Memory

CLI Memory 的召回发生在 Agent 构建前

CLI 通过 MemoryRuntime 把项目级 SQLite 长期记忆和当前 Session Working Memory 接入 AgentSession。它不是在模型中途随意查询，而是在每次 Submit 构建 Agent 上下文前按 Prompt 检索。

自动检索时机 每次 CLI Submit / Stage 执行前，recall(query=prompt) 先完成，再把有界 Memory Context 注入 Agent Instructions。
手动检索入口 /memory search [--class working|semantic|procedure|scenario] <query> 直接查 Memory Controller，不触发模型回合。
写入时机 工业 Eval 开启时仅 accepted 输出可自动晋升；未开启时要求 Agent 成功且通过领域 Validator。随后先提取 Working Memory，再 consolidate 成长期记忆。
压缩关系 Context Compact 不是 Memory 检索；它压缩 Session History。Memory Recall 仍在下一次 Agent 上下文构建前重新发生。

`/compact` 只改变 Conversation History，不删除 SQLite Memory、Working Memory、Task、Checkpoint 或 Atomic Flow。没有 Summarizer 时失败；CLI 注入的兼容单轮 Agent Session 不提供该命令能力。

默认压缩阈值

compactAtContextRatio=0.7，目标摘要约为 compactToContextRatio=0.25。摘要替换历史为一条 assistant summary。

存储位置

失败模式

best-effort 只记录降级；strict 会把 Memory 基础设施错误提升为运行失败。

Component Architecture / Evals

Component Architecture / Sandbox

隔离包只编译启动边界，不替调用方运行命令

@yiku/sandbox 接收已授权的 Workspace、网络策略和运行时只读路径， 生成可交给 Node spawn() 的启动描述。命令分类、审批、子进程管理和 Host Policy 降级始终由上层拥有。

Validated InputShellSandboxWorkspace 已完成授权、规范化和 Real Path 校验；Sandbox 不重新解释权限。
Platform CompilermacOS 编译 sandbox-exec Profile；Linux 编译 rootless bubblewrap Namespace 参数。
Availability Probe每次 createLaunchSpec() 都先验证隔离器可执行且能启动，受控测试可显式跳过。
Caller Ownership调用方 spawn、取消、收集输出并等待退出；最后调用幂等 close() 清理实例资源。

    "-p",

      ? "(allow network*)" : ""

Linux / rootless bubblewrap 
launchSpec {
  command: "bwrap"
  args: [
    "--unshare-all", "--cap-drop", "ALL",
    "--tmpfs", "/tmp",
    "--ro-bind", runtimeRoot, runtimeRoot,
    access === "read-only"
      ? ["--ro-bind", workspace, workspace]
      : ["--bind", workspace, workspace],
    network === "allow" ? "--share-net" : [],
    "--chdir", cwd, "--", shellPath
  ]

Workspace 与 ~/.yiku 必须先由上层完成 Real Path 授权； macOS 通过 deny-default Profile 和私有 Home/Temp 收口，Linux 通过 Namespace、只读运行时挂载、 Workspace bind 与 Network Namespace 收口。隔离器不可用时抛出 SHELL_SANDBOX_UNAVAILABLE，不会在包内静默回退 Host。

资源生命周期

macOS 临时目录属于 Sandbox 实例；所有使用其启动描述的子进程退出后才能 close()。

降级语义

HostPolicyShellSandbox 是显式弱边界。Code Terminal 可记录降级后继续，Verification Command 必须拒绝。

复用位置

持久 BashTerminal、结构化 Verification Command 和自定义 Node Host 共享同一启动契约。

Component Architecture / Permission

Permission 是 Runtime 决策，不是工具自己的选择

权限链路把 Workspace 边界、命令风险、Session Grant、长期 Profile、Hook 建议和 Runtime 硬拒绝合并成一个可解释决策。

Audit Boundary审批缓存只匹配相同 Workspace、工具、能力、风险和目标；展示截断文本不作为授权依据。

Component Architecture / Hooks

Hooks 把策略挂在生命周期边界上

Hook Engine 负责编译配置、匹配事件、调度六类 Executor、合并 Decision、记录脱敏审计；Runtime 负责尊重最终边界。

Config CompilerManaged、User、Project、Plugin、Skill/Agent、Runtime Callback 多来源编译成不可变 Snapshot。
Matcher / Condition按事件结构字段匹配，不执行任意 JavaScript；配置更新失败不替换旧 Snapshot。
Executor Registrycallback、command、http、prompt、agent、mcp 都有超时、字节、网络和取消限制。
Decision Policyallow、block、defer、no-op、stop 与权限建议合并；Hook allow 不能覆盖 Runtime deny。
